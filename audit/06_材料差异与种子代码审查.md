# 06 材料差异与种子代码审查

> **对象**：`data-dictionary.md`、`seed.py`。
> **方法**：以 `PRAGMA table_info`、`sqlite_master`、全表取值统计为事实基准，逐字段/逐行比对；`seed.py` 采用静态审查 + 隔离副本运行探针（不触碰原始数据库）。
> **结论**：字典有 **4 个实质性错误/遗漏**；`seed.py` 的核心逻辑全部缺失，且存在静默丢行风险，不能满足任何一条验收标准。

## A.3 一致项（已核实，不是“默认相信”）

以下内容经过实际查询或全表统计，与字典一致：

- 3 张表的表名、字段名（除 `risk_level` 外）、声明类型；
- `sku_info` 的 8 个类目、5 种币种；

## A.4 差异结论

- **实质性错误 4 个**：`is_deleted` 遗漏、`severity` 字段名、`CNY/RMB`、`sku_ref` 直接关联；
- **文档遗漏 2 类**：约束/默认值/行数、`is_deleted` 字段说明；
- **一致项**：表数量、表名、大部分字段名与类型、枚举、编号格式；
- 所有差异都已映射到第二阶段的处理方式，不能为了“让程序跑起来”而修改业务定义或原始数据。

## B.2 隔离运行探针

为避免触碰原始数据库，将 `seed.py`、`compliance.db`、`sku_list.csv` 复制到独立目录后运行：

```text
退出码：0
stdout：处理完成，共 120 条
```

- 运行目录中没有生成任何报告文件；
- 副本运行前后 SHA-256 与原始文件一致（`compliance.db` 未被修改）；
- 探针记录见 [seed_probe.log](seed_probe.log)。

**说明**：程序“打印 120 条”只证明循环跑完，不代表业务成功。结合第 23 行的直接等值查询，120 条的查询全部未命中；因此每条记录实际是：

```text
sku_ref = 原始 5 位编号
name    = "(未找到)"
risk    = "待补充"
```

这既不是“库中缺失”的规范处置，也不是任何一档合法风险。

## B.3 静默丢失的具体场景

`except Exception: pass` 会在以下场景把记录直接从 `report` 中抹掉，且进程仍以退出码 0 结束：

1. **表/列不存在**：例如按字典写 `risk_level`，或数据库版本不含 `is_deleted`；每次查询抛 `OperationalError`，逐条跳过；
2. **数据库文件不存在**：`sqlite3.connect` 会创建一个空库，随后查询 `no such table`，所有行被跳过，最终“共 0 条”；
3. **CSV 表头变化**：`row["sku_ref"]` 抛 `KeyError`，逐条跳过；
4. **Schema 变化**：查询成功但 `sku["name"]` 抛 `KeyError`，逐条跳过；
5. **数据库锁定/IO 错误**：逐条跳过；
6. 任何未来新增代码中的异常（包括程序 bug）也会被吞掉。

由于没有 `len(report) == 120` 的最终断言，丢行不会触发失败；这正是验收条件“不允许静默丢失”要禁止的模式。

## B.5 可保留的部分

`seed.py` 并非一无是处，以下做法可以在重写时保留：

1. `encoding="utf-8-sig"`：正确处理 BOM，避免首列名带 `﻿`；
2. 参数化 SQL（`?` 占位符）：避免 SQL 注入与拼接错误；
3. `row_factory = sqlite3.Row`：按列名访问，可读性尚可；
4. 结构简单，适合作为“反例”说明为什么不能直接交付。

## B.6 结论与第二阶段建议

`seed.py` 只能证明“能连库、能读 CSV、能循环”，**不能作为交付基础**。第二阶段建议：

1. **重写加载模块**：显式校验表头、记录数、编码、空值；
2. **映射层**：`strip + "SKU-"`，保留原始 `sku_ref`，缺失显式标记；
3. **状态层**：先缺失、再 `is_deleted`、否则正常评估；
4. **规则引擎**：按 [04_规则库审计与业务口径.md](04_规则库审计与业务口径.md) 的三条件与最严优先级；
5. **价格模块**：`Decimal` + 数据库实际汇率 + 2 位小数；
6. **报告模块**：明细 120 行、汇总三档/Top 类目、完整性五数；
7. **异常策略**：禁止裸 except；逐条记录异常，最终断言总数；
8. **测试**：覆盖 5 条缺失、5 条下架、5 种币种、规则边界、重复批次、未知风险值、汇率缺失。

> 本轮未修改 `seed.py`，也未把它的任何逻辑复制进审计脚本；审计脚本仅做只读检查。
