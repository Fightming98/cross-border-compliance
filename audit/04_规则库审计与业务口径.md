# 04 规则库审计与业务口径

> **对象**：`compliance_rules`（10 条）与 `instructions.md` 2.1 的规则匹配口径。
> **方式**：只读 SQL 全表检查 + 分隔符/取值/引用完整性校验；本阶段**不**逐 SKU 计算风险。
> **关键结论**：真实风险字段是 **`severity`**（不是字典的 `risk_level`）；实际取值 **待确认 8 条、违规 2 条**；规则类目/材质/产地无悬空引用；匹配口径可按题目原文固定。

| 检查项 | 方法 | 结果 |

| 规则总数 | `SELECT COUNT(*)` | **10** |
| 字段名/类型 | `PRAGMA table_info(compliance_rules)` | 与上文一致；风险字段为 `severity` |
| 主键唯一 | `rule_id` PK / 重复统计 | 无重复 |
| `rule_id` 格式 | 模式统计 | 10/10 为 `CR-999` |

| 材质分隔符 | 按 `\|` 分列，检查空 token/空格 token | 无问题 |
| NULL | 逐列 `COUNT(*) WHERE col IS NULL` | 所有列 0 |
| 空字符串 | 逐列 `TRIM(col)=''` | 仅 `origin_keyword` 8 条；其余 0 |
| 前后空格 | `col <> TRIM(col)` | 0 |
| 类目引用 | 规则类目 token 是否都在商品类目集合 | 全部存在，悬空 0 |

### 1. 类目覆盖

规则涉及的类目并集（8 个）：

```text
上衣, 内衣, 箱包, 裙装, 裤装, 配饰, 针织衫, 鞋靴
```

与 `sku_info.category` 的 8 个实际取值完全一致；无规则引用了商品表中不存在的类目。

### 2. 材质关键词覆盖

| 关键词 | 商品中包含该关键词的材质 | 悬空？ |
|---|---|---|
| PU革 | PU革 | 否 |
| 不锈钢 | 不锈钢 | 否 |
| 再生涤纶 | 再生涤纶 | 否 |
| 合金 | 合金 | 否 |
| 棉 | 棉 | 否 |
| 牛皮 | 牛皮 | 否 |
| 真皮 | 真皮 | 否 |
| 羊毛 | 羊毛 | 否 |
| 羊皮 | 羊皮 | 否 |
| 羊绒 | 羊绒 | 否 |

> 重要观察：在当前数据中，每个关键词都只命中一个**同名材质**，没有出现“关键词是另一个材质的子串”的误伤。例如 `棉` 没有出现在 `锦纶`、`涤纶`、`再生涤纶` 中。因此按题目规定的“子串包含”实现，不会在当前数据上产生额外误匹配。未来若新增材质（如“棉混纺”），子串语义会自然命中，这是题目口径，不是 bug。

### 3. 产地覆盖

规则产地关键词只有两个：

- `意大利`（CR-004）：商品表中存在，8 条商品；
- `越南`（CR-008）：商品表中存在，22 条商品。

无悬空。

### 4. 空值的真实表示

- `origin_keyword` 的“不限”使用**空字符串 `''`**，不是 NULL；
- `material_keyword` 在 DDL 中允许 NULL，但当前 10 条全部非空；
- 代码若只判断 `IS NULL` 会漏掉 8 条空字符串规则，从而把“不限产地”误判为“产地必须为空”，导致规则失效。**必须同时处理 NULL 与 `strip()==''`。**

## 三、正式匹配口径（第二阶段实现契约）

以下口径来自 `instructions.md` 2.1，并结合真实字段名落地。

### 1. 单条规则生效条件

对商品 `sku` 与规则 `rule`：

#### 条件一：类目

```text
sku.category 出现在 rule.applies_to_category.split(",") 的任一项中
```

- 使用**完全相等**，不是子串；
- 分列后对每个 token 做 `strip()`；空 token 视为数据错误；
- 实际数据无空格、无空 token。

#### 条件二：材质

```text
若 rule.material_keyword 为空（NULL 或 strip 后为空）→ 不限，条件通过
否则：
    keywords = rule.material_keyword.split("|")，逐项 strip，丢弃空 token
    sku.material 包含 keywords 中任意一个关键词（子串包含）→ 通过
```

- “为空”必须同时覆盖 `None` 和 `""`/纯空白；
- 关键词匹配是**子串包含**，区分大小写（中文无大小写；`PU革` 按原样匹配）；
- 若原始字段非空但分列后没有任何有效 token（例如只有 `||`），应视为规则数据错误并显式失败，不能静默当作“不限”。

#### 条件三：产地

```text
若 rule.origin_keyword 为空（NULL 或 strip 后为空）→ 不限，条件通过
否则：sku.origin.strip() == rule.origin_keyword.strip()
```

- 使用**完全相等**，不是子串；
- 实际数据无前后空格；`strip` 只是防御性规范化。

#### 组合

```text
三个条件同时满足（AND）→ 规则生效
```

### 2. 多条规则命中的风险聚合

设某 SKU 的生效规则集合为 `H`：

```text
if H 为空:
    risk = "合规"
    rule_ids = "—"
else:
    risk = max(H.severity, 优先级: 违规 > 待确认)
    rule_ids = H 中所有 rule_id，按 rule_id 升序，用 ";" 连接
```

- 风险优先级：**违规（2） > 待确认（1）**；`合规` 是“无命中”的默认值，不是规则取值；
- **建议列出全部生效规则编号**，而不是只列最严的一条：这样“依据规则”可完整追溯；最严等级单独体现在风险标记中。该呈现方式需在 README 固定；
- 若 `severity` 出现 `{待确认, 违规}` 之外的任何值，**显式报错**，不得静默降级为合规或待确认；
- 若同一 `rule_id` 重复出现（当前主键约束下不可能），应按数据错误处理。

### 3. 状态优先级

规则匹配只对 **正常评估** 商品执行：

```text
库中缺失 → 不匹配规则，风险/规则编号不适用
已下架   → 跳过规则评估，风险/规则编号不适用
正常评估 → 执行规则匹配
```

不能对已下架/缺失商品输出“合规”，否则会被误解为“已评估且合规”。

### 4. 规范化建议

| 对象 | 建议 | 对本数据的影响 |
|---|---|---|
| `sku_ref` | `strip` 后加 `SKU-` 前缀 | 必需 |
| `category` | `strip` 后精确比较 | 无变化（已干净） |
| `material` | `strip` 后子串比较 | 无变化 |
| `origin` | `strip` 后精确比较 | 无变化 |
| 规则类目/材质 token | 分列后逐项 `strip` | 无变化 |
| 空字符串/NULL | 统一视为“不限” | 影响 8 条 origin 规则 |
| 大小写 | 不做统一转换 | 当前 `PU革` 精确匹配；转换反而可能改变语义 |

## 四、规则边界与第二阶段测试清单

本阶段不逐 SKU 计算，但下列用例必须在第二阶段规则引擎中覆盖：

### 1. 单条件边界

| 用例 | 输入要点 | 期望 |
|---|---|---|
| 类目精确命中 | `category=鞋靴`，规则 `鞋靴,箱包,配饰` | 命中 |
| 类目不命中 | `category=内衣`，规则只含 `鞋靴` | 不命中 |
| 类目不得子串匹配 | `category=靴`（假设值） | 不应命中 `鞋靴` |
| 材质为空不限 | `material_keyword=''` | 条件通过 |
| 材质 NULL 不限 | `material_keyword=NULL` | 条件通过 |
| 材质子串命中 | `material=棉`，keyword=`棉` | 命中 |
| 材质不误伤 | `material=锦纶`，keyword=`棉` | 不命中 |
| 多关键词任一命中 | keyword=`合金\|不锈钢`，material=`不锈钢` | 命中 |
| 产地为空不限 | `origin_keyword=''`，任意 origin | 条件通过 |
| 产地精确命中 | origin=`意大利`，keyword=`意大利` | 命中 |
| 产地不得子串 | origin=`意大利`，keyword=`意大` | 不命中 |
| 产地不同 | origin=`越南`，keyword=`意大利` | 不命中 |

### 2. 组合边界

| 用例 | 期望 |
|---|---|
| 箱包 + 真皮 + 意大利 | 命中 CR-001（待确认）和 CR-004（违规）→ 最终 **违规** |
| 箱包 + 真皮 + 越南 | 命中 CR-001（待确认），不命中 CR-004 → 最终 **待确认** |
| 鞋靴 + PU革 + 越南 | 命中 CR-002（待确认）和 CR-008（待确认）→ 最终 **待确认** |
| 鞋靴 + PU革 + 意大利 | 命中 CR-002，不命中 CR-008 → 最终 **待确认** |
| 鞋靴 + 牛皮 + 任意产地 | 命中 CR-001 与 CR-010（均待确认）→ 最终 **待确认**，规则编号两个 |
| 内衣 + 再生涤纶 | 命中 CR-007 → **违规** |
| 内衣 + 棉 | 命中 CR-006 → **待确认** |
| 上衣 + 涤纶 + 中国 | 无命中 → **合规**，规则编号 `—` |
| 已下架商品 | 不进入规则引擎，风险不适用 |
| 库中缺失商品 | 不进入规则引擎，风险不适用 |

> 上述“期望”是匹配逻辑的测试预期，不是本轮对真实 SKU 的风险统计。本轮没有运行逐 SKU 判定，因此不给出三档真实数量。

### 3. 数据错误边界

| 用例 | 期望 |
|---|---|
| `severity='高风险'` | 显式报错（未知风险等级） |
| `applies_to_category=''` | 显式报错（规则无适用类目） |
| `applies_to_category='鞋靴,,箱包'` | 显式报错（空 token） |
| `material_keyword='|'` | 显式报错（无有效关键词） |
| 规则表 0 行 | 视为配置错误或明确输出全部合规？需在 README 固定；建议报错，避免空规则库被误认为“全部合规” |
| 汇率缺失 | 价格模块显式报错，不跳过商品 |

## 五、结论

1. 规则库结构完整、取值合法、无悬空引用，可以支撑第二阶段。
2. 真实风险字段是 `severity`，不是 `risk_level`；这是 P0 级字典差异。
3. `origin_keyword` 有 8 条空字符串，代码必须把 `NULL` 与 `''` 都当作“不限”。
4. 类目/材质/产地的匹配方式分别为：精确成员、子串任一、精确相等；三者 AND。
5. 多规则命中取 `违规 > 待确认`；无命中为 `合规`；未知 `severity` 应报错。
6. 已下架/缺失商品不参与规则评估，不能输出“合规”。
7. 本阶段只确认口径，没有提前实现逐 SKU 判定，也没有生成风险统计。
