## 三、总体架构设计

### 3.1 分层

| 层 | 职责 | 关键文件 |
|---|---|---|
| 业务核心 | CSV/SQLite 加载、规则匹配、价格换算、结果校验 | 原有 `loader`、`processor`、`rules_engine`、`pricing`、`validation` |
| 应用服务 | 一次检查的统一执行与结果快照、JSON/CSV 呈现 | `application_service.py` |
| 报告展示 | Markdown、单文件 HTML | 原有 `report.py`、新增 `html_report.py` |
| Web 适配 | 路由、上传、错误映射、安全响应头、下载 | `web_app.py` |
| 任务存储 | 随机任务 ID、固定目录、允许列表、删除与过期清理 | `job_store.py` |
| 可观测性 | 控制台/文件双输出、轮转、任务上下文、错误编号 | `logging_config.py` |
| 前端 | 上传、状态、统计卡、CSS 图表、筛选、排序、分页、下载 | `templates/`、`static/` |

### 3.2 统一数据流

```text
CSV + 只读 SQLite
        ↓
  load_sku_inputs / load_products / load_rules / load_exchange_rates
        ↓
  validate_sku_inputs / validate_database_snapshot
        ↓
  process_sku_inputs（原有映射、状态、规则、价格流程）
        ↓
  validate_processing_results（原有完整性校验）
        ↓
  ComplianceRun 统一结果快照
        ↓
 ┌───────────┬───────────┬───────────┬───────────┐
 │ Markdown  │ HTML 报告 │ Web API   │ CSV 明细  │
 └───────────┴───────────┴───────────┴───────────┘
```

`ComplianceRun` 包含：

- 120 条 `ProcessingResult` 与原始 `SkuInput`；
- 完整性统计 `IntegrityStats`；
- 商品、规则、汇率快照；
- 源文件名、SHA-256、字节数、生成时间；
- 风险、处置计数；
- Top 风险类目。

所有入口只读取该对象。前端筛选、排序和分页不重算业务；HTML 模块不重算价格；CSV 模块不重算风险。

### 3.3 入口一致性边界

CLI 与 Web 共用 `run_compliance_check`，差异仅限调用参数：

| 参数 | CLI 默认 | Web |
|---|---|---|
| `expected_input_count` | `120` | `None`（允许任意非空合法清单） |
| `source_filename` | 本地文件名 | 清理后的上传显示名 |
| `generated_at` | 当前时间 | 当前时间 |
| HTML `report_id` | 无 | 任务 ID |

`expected_input_count=None` 不会放宽 CSV 表头、编码、SKU 格式、数据库或规则校验，只解除“必须恰好 120 行”的限制，使 Web 可以检查符合契约的其他清单。

## 四、后端实现

### 4.1 应用服务层

`src/compliance_assistant/application_service.py` 提供：

```python
run_compliance_check(csv_path, db_path, *,
                     expected_input_count=None,
                     source_filename=None,
                     generated_at=None) -> ComplianceRun
build_result_payload(run, job_id, *, links=None) -> dict
build_details_csv(run) -> str
write_details_csv(run, output_path) -> Path
```

实现要点：

- 复用原有加载、处理、校验模块，不复制规则或价格逻辑；
- 用 `Counter`/枚举初始化风险与处置计数，避免遗漏；
- `risk_ratio = (待确认 + 违规) / 实际评估`，分母为 0 时返回 0；
- CSV 带 UTF-8 BOM，固定 15 列，明细顺序与输入一致；
- CSV 使用临时文件 + `os.replace` 原子写入，写后复核行数，失败清理；
- JSON 载荷含汇总、完整性等式、Top 类目、规则表、120 条明细和下载链接；
- 占位规则：缺失商品用“—”；已下架商品的人民币价格、风险、规则用“—（不适用）”。

### 4.2 Flask 应用

`web_app.py` 提供应用工厂 `create_app(test_config)` 和本地入口 `main()`。

默认配置：

| 配置 | 值 |
|---|---|
| 监听地址 | `127.0.0.1`（固定） |
| 默认端口 | `5000`，可 `--port` 指定 |
| debug / reloader | `False` / `False` |
| 数据库 | 项目根目录 `compliance.db` |
| 结果目录 | `reports/web_runs` |
| 日志 | `logs/application.log` |
| 单文件上限 | 2 MB |
| 请求上限 | 2 MB + 64 KB |
| 任务保留期 | 7 天 |
| 上传临时目录 | 系统临时目录，请求结束自动删除 |

实际路由：

```text
GET    /
POST   /api/reports
GET    /api/reports/<job_id>
GET    /reports/<job_id>
GET    /api/reports/<job_id>/download/markdown
GET    /api/reports/<job_id>/download/html
GET    /api/reports/<job_id>/download/csv
DELETE /api/reports/<job_id>
```

上传处理顺序：

1. 生成随机任务 ID；
2. 检查 multipart 字段 `file`（兼容 `csv`）和文件名；
3. 校验 `.csv` 扩展名；
4. 以 64 KB 分块流式写入系统临时文件，边写边累计大小，超过 2 MB 立即拒绝；
5. 拒绝空文件；
6. 调用统一应用服务；
7. 在 `reports/web_runs/<job_id>/` 生成 Markdown、HTML、CSV 和 `result.json`；
8. 写后复核 Markdown 行数/SKU，CSV 行数，HTML 必需区块与 120 行；
9. 返回统一 JSON。

失败时不会把旧结果冒充新任务；已创建的不完整任务目录会被清理。

### 4.3 错误模型

结构化错误：

```json
{
  "ok": false,
  "error": {
    "code": "invalid_csv",
    "message": "CSV 校验失败：……",
    "error_id": "ERR-XXXXXXXX"
  }
}
```

- 客户端输入错误：400；
- 文件/请求过大：413；
- 任务不存在、已删除、已过期、非法类型：404；
- 方法不允许：405；
- 服务端处理、存储、报告生成失败：500。

浏览器永远不会收到 Python traceback；完整异常堆栈只写入本地日志，并带同一个错误编号。

### 4.4 任务存储

`job_store.py`：

- 任务 ID：`secrets.token_hex(16)`，32 位小写十六进制；
- 正则校验：`^[0-9a-f]{32}$`；
- 任务目录：`root/<job_id>/`，`resolve()` 后必须仍直接位于 root；
- 下载类型只允许 `markdown`、`html`、`csv`；
- 文件名由服务端允许列表固定；
- 快照限制 5 MB，且 `job_id` 必须与目录一致；
- 删除使用受控递归删除，Windows 权限占用时有限重试；
- 过期清理只处理 root 直属、非符号链接、合法 ID 目录的 7 天前结果。

### 4.5 日志

`logging_config.py`：

```text
格式：%(asctime)s | %(levelname)-7s | job=%(job_id)s | %(message)s
文件：logs/application.log
轮转：1,000,000 字节 × 5 个备份
输出：控制台 + 文件
```

实际记录事件包括：

```text
app_start
task_received
upload_received size_bytes=...
check_completed n_input=... n_matched=... n_deleted=... n_missing=...
reports_generated markdown_bytes=... html_bytes=... csv_bytes=...
task_completed duration_ms=...
job_read / report_page_opened / download kind=...
job_deleted
request_rejected / request_failed / unhandled_exception
```

日志只记录数量、状态、大小和任务 ID，不记录完整 CSV 或整表业务明细。验收结束时日志为 240 行、30,716 字节。

## 五、HTML 报告设计

`html_report.py` 消费 `ComplianceRun`，生成单文件报告：

- 顶部：标题、生成时间、输入文件名、状态、报告编号、版本；
- 概览：8 项统计；
- 风险分布：三档数量与占实际评估数比例；
- 处置分布：正常评估、已下架、库中缺失；
- Top 风险类目；
- 120 条完整明细：SKU、批次、处置、名称、类目、材质、产地、原价、人民币价格、风险、命中规则；
- 完整性校验：三条数量等式与风险总数等式；
- 底部：风险等级、处置状态、人民币换算与统计口径说明。

离线与安全：

- 所有 CSS 内嵌；
- 不包含 `<script>`，不引用 CDN、HTTP(S)、远程字体、网络图片；
- 所有外部文本经过 `html.escape(..., quote=True)`；
- 不使用未经校验的数据库文本拼接 JavaScript；
- 图表只使用 HTML/CSS 条和数值文本；
- 生成时校验必需区块、120 行和外部资源；
- 原子写入后重新读取复核；失败时清理临时文件。

`generated_at` 和 Web 任务编号会进入 HTML，因此同一数据的 CLI HTML 与 Web HTML 字节不同；120 行业务字段、汇总和 Top 类目完全一致。

## 七、安全设计

| 风险 | 措施 |
|---|---|
| 任意文件上传 | 仅 `.csv`；前端预检 + 后端扩展名/表头/编码校验 |
| 超大文件 | 2 MB 流式上限 + Flask 请求上限，超限 413 |
| 客户端指定路径 | 任务目录、数据库、结果文件名全部服务端固定 |
| 路径穿越 | 任务 ID 正则、目录 `resolve` 边界、下载允许列表 |
| 可预测任务 | 128 位随机十六进制 ID |
| 原始上传残留 | 系统 `TemporaryDirectory`，请求结束自动删除 |
| XSS | Jinja2 自动转义；客户端 `textContent`；HTML 报告 `html.escape` |
| 调试信息泄漏 | `debug=False`；API 统一错误；无 traceback |
| 点击/框架攻击 | CSP、`X-Frame-Options: DENY`、`nosniff` |
| 结果缓存 | `/api/` 与 `/reports/` 设置 `Cache-Control: no-store` |
| 外部依赖 | 无 CDN、远程字体、网络图片、在线图表 |
| 日志泄漏 | 只记数量/大小/任务 ID，不记完整 CSV |
| 网络暴露 | 固定绑定 `127.0.0.1`，不监听 `0.0.0.0` |

CSP 实际值：

```text
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
img-src 'self' data:; connect-src 'self'; object-src 'none';
base-uri 'none'; frame-ancestors 'none'
```

`style-src` 允许内联样式以支持模板图表宽度；`script-src` 仍只允许本地文件，页面无内联脚本。该 CSP 不改变“本地演示应用”的安全边界。

## 十一、已知限制与未完成事项

### 11.1 设计边界

1. 使用 Flask 开发服务器，面向本地演示，不是生产服务器；
2. 无身份认证、用户隔离、CSRF Token、限流、HTTPS、反向代理；
3. 任务链接本身是访问凭证，拿到完整 URL 即可读取结果，不应在不可信网络共享；
4. 同步处理上传，未引入队列，适合当前 120 行规模；2 MB 上限不是大规模批处理方案；
5. 7 天清理只在应用启动时执行，没有后台定时线程；
6. `is_deleted=1` 的业务语义、JPY/KRW 价格量级仍是实现假设，等待业务方确认；
7. HTML 因任务编号/生成时间不同而哈希不同；一致性以 120 行逐字段核对为准；
8. 浏览器验收依赖本机 Chrome + Playwright，未写入运行依赖；没有该环境时，应用和 174 个测试不受影响；
9. CSP 为支持模板图表宽度允许内联样式，但脚本仍严格限制为 `'self'`；
10. 未对公网部署所需的安全、审计、备份、密钥管理作任何承诺。

### 11.2 未完成项目

在本阶段提示词要求的范围内，**没有未实现的功能**。以下为有意不做或超出本阶段范围的事项：

| 事项 | 原因 |
|---|---|
| 用户登录与权限 | 本地单用户演示，题目未要求 |
| HTTPS / 公网部署 | 明确要求不将本地应用直接开放到公网 |
| 任务队列与并发处理 | 当前规模不需要，引入会增加部署复杂度 |
| 后台定时清理 | 启动时清理已满足本地清理策略 |
| 内嵌 JavaScript 的 HTML 报告 | 报告采用纯 HTML/CSS 即可完成展示，减少离线脚本攻击面 |
| Playwright 作为强制运行依赖 | 浏览器测试为可选环境能力，应用本身不需要 |
