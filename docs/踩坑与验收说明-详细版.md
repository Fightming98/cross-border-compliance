## 二、实现中固定的口径

1. **状态顺序**：先查商品是否存在，再判断 `is_deleted`；缺失 → 已下架 → 正常评估。`is_deleted` 非 0/1 直接报错。
2. **在库数**：可关联到商品库的输入记录数，包含已下架，正式数据为 115。
3. **规则匹配**：类目精确成员、材质任一关键词子串、产地完全相等，三条件 AND；空/NULL/纯空白视为“不限”。
4. **风险聚合**：命中多条取最严，规则编号全部保留并按 `rule_id` 升序、以 `;` 连接；无命中为“合规”。
5. **价格**：`Decimal(str(value))`，`ROUND_HALF_UP` 保留两位；只用数据库汇率，不硬编码。
6. **缺失/下架**：不进入规则引擎和价格模块；报告分别使用“—”和“—（不适用）”，不伪装成“合规”。
7. **Top 风险类目**：违规数降序 → 待确认数降序 → 类目名升序，取前 5；这是实现口径，不是题目指定的唯一算法。
8. **`is_deleted=1` = 已下架**：高置信度推断，尚未获得业务方单独确认，README 已如实标注。
9. **舍入方式**：题目未规定，采用 `ROUND_HALF_UP`；如业务方要求银行家舍入，需修改并同步测试。
10. **入口统一**：CLI、Web、HTML、CSV 都消费同一个 `ComplianceRun`，展示层不重算业务。

## 五、第五阶段实际踩坑与修复

| # | 现象 | 根因 | 处理与验证 |
|---:|---|---|---|
| 1 | 390px 窄屏出现 5px 页面级横向溢出 | 32 位任务 ID 在 151px 宽的两列 flex 中无法收缩 | 任务编号单元格独占一行，长值 `overflow-wrap:anywhere`；390/320px 均测得 0px |
| 2 | Playwright 删除任务后报 CSP `unsafe-eval` | `wait_for_function` 使用字符串求值，被 `script-src 'self'` 拦截 | 改为等待 `#results-panel[hidden]` 选择器；不放宽 CSP |
| 3 | 浏览器把三类下载记录为失败请求 `net::ERR_ABORTED` | Chrome 下载交接会中止原导航请求，不是服务器错误 | 从成功的 `expect_download` 收集 URL，并从意外失败列表中排除；恰好 3 个，其他失败仍会使测试失败 |
| 4 | 全页截图中间重复出现顶栏、跳转链接 | 整页截图对 `position: sticky/fixed` 元素分段绘制产生伪影 | 仅截图前将顶栏设为 static、隐藏跳转链接；正常交互验收仍使用粘性顶栏 |
| 5 | 390px 下 “SKU DETAILS” 与结果计数拥挤换行 | 标题与结果计数同行，宽度不足 | 移动端把 `.details-heading` 改为纵向排列 |
| 6 | 任务结果下载响应仍可能被缓存 | `send_file` 默认 `no-cache` 不等于禁止存储 | 对 `/api/` 和 `/reports/` 统一设置 `Cache-Control: no-store`，测试覆盖 |
| 7 | 重复清单行可能在 Web 层被误去重 | 业务契约要求逐行保留，测试需固定该行为 | 增加重复行保留测试；120 行完整进入任务，不去重、不静默丢弃 |
| 8 | 导入 `web_app` 可能产生正式日志/目录副作用 | Flask 入口与模块导入混在一起 | 仅在 `python web_app.py` 的 `__main__` 中启动；测试通过 `create_app(test_config)` 使用临时日志、结果和数据库 |
| 9 | 上传错误时控制台出现一条预期 400 | 浏览器错误页/网络层会记录失败的 HTTP 请求 | 浏览器脚本只允许明确的预期 400，其余控制台错误仍判失败；记录 `expected_http_400_console_messages=1` |
| 10 | HTML 文件哈希与 CLI 不一致 | Web HTML 包含任务编号和生成时间，CLI HTML 不包含 | 不把字节相等作为 HTML 验收条件；独立核对 120 行字段、汇总和 Top 类目完全一致 |

此外，浏览器首行原价断言按“原价 + 币种”显示为 `178.97 KRW`，不是人民币价格；该显示由服务端结果直接渲染，业务值未改写。验收时以真实 DOM 文本为准，避免把格式差异误判为业务错误。

## 六、HTML 报告与本地应用的安全边界

已实现：

- HTML 单文件、无 JavaScript、无外部 CSS/字体/图片/图表；
- 所有商品/CSV/SQLite 文本 HTML 转义；
- Web 上传仅 CSV、2 MB，数据库和输出路径服务端固定；
- 任务 ID 128 位随机，目录和下载文件允许列表；
- 调试关闭、仅绑定 `127.0.0.1`、统一错误、无 traceback；
- CSP、`X-Frame-Options`、`nosniff`、`Referrer-Policy`、`no-store`；
- 日志不记录完整 CSV，轮转 1 MB × 5。

未实现：

- 登录、用户隔离、CSRF、限流、HTTPS；
- 公网部署、多用户审计、备份和密钥管理；
- 后台定时清理（只在启动时清理 7 天前任务）。

因此，本项目只能作为**本地演示与测试应用**，不能描述为已经完成公开互联网部署。

## 七、未解决事项与边界

- `is_deleted=1` 的业务语义、JPY/KRW 价格量级仍需业务方确认；当前按实现假设处理，不把假设写成已确认事实。
- 如果出现非法 `severity`、空规则表、空类目、缺失汇率、损坏数据库、物理空行或重复表头，程序会显式失败，不会自动降级或跳过。
- 第三阶段修复的 7 个问题均已回归验证；第五阶段未发现新的业务代码缺陷。
- 第五阶段新增的功能已在本地实际运行验证；浏览器验收依赖本机 Chrome + Playwright，属于可选验收环境，不是运行依赖。
- 7 天保留期只在应用启动时执行清理；运行期间可手动删除任务。
- HTML 报告每次生成可能因时间/任务编号不同而哈希不同，业务一致性以逐字段核对为准。
- 第四阶段最终验收结论仍为“最终验收通过”；本阶段没有覆盖或修改第四阶段证据。
- 第五阶段验收结论为“通过（本地演示与测试范围内）”，不等于公网生产验收。
