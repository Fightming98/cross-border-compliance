# 踩坑与验收说明

> 项目：跨境商品合规检查助手（AI 全栈工程师校招笔试）
> 本说明只记录实际检查、实际运行和实际测试过的内容，不替代 README。

## 一、材料中发现的问题

| # | 问题 | 怎么发现 | 怎么处理 |
|---|---|---|---|
| 1 | 数据字典写 `risk_level`，真实列为 `severity` | 第一阶段 `PRAGMA table_info(compliance_rules)` | 全部代码使用 `severity`，不按字典写 SQL |
| 2 | 数据字典漏掉 `sku_info.is_deleted` | 对比 `PRAGMA table_info` 与字典字段清单 | 状态判定读取 `is_deleted`；5 条 `=1` 标记“已下架” |
| 3 | 字典写人民币代码 `RMB`，实际为 `CNY` | 全表读取 `exchange_rates` | 汇率按数据库实际值读取；CNY 商品使用 CNY 行 1.0 |
| 4 | 字典称 `sku_ref` 可直接等于 `sku_id` | 直接相等匹配 0/120；加 `SKU-` 前缀后 115/120 | 统一 `SKU-` + 五位数字映射；保留原始值 |
| 5 | 清单有 5 个真实缺失 SKU | 映射后与 `sku_info` 比对 | 00031、00057、00084、00099、00113 显式标记“库中缺失”，不丢弃 |
| 6 | `seed.py` 用裸 `except Exception: pass` | 逐行审查 + 隔离副本运行 | 新实现禁止裸吞异常；单条错误带 SKU 上下文抛出，最终强制核对总数 |
| 7 | `seed.py` 直接查询 5 位编号，0/120 命中 | 静态审查 + 隔离探针 | 重写映射层，不复用种子逻辑 |
| 8 | `batch_no` 有 9 个重复值、涉及 19 条记录 | 全量统计 | 批次号仅展示和追溯，绝不按批次去重；120 条逐行保留 |
| 9 | JPY/KRW 换算后金额明显偏低 | 按数据库汇率试算 | 不修改原价/汇率，按题目公式照常换算，仅在本说明和 README 记录 |

## 二、实现中固定的口径

1. **状态顺序**：先查商品是否存在，再判断 `is_deleted`；缺失 → 已下架 → 正常评估。`is_deleted` 非 0/1 直接报错。
2. **在库数**：可关联到商品库的输入记录数，包含已下架，正式数据为 115。
3. **规则匹配**：类目精确成员、材质任一关键词子串、产地完全相等，三条件 AND；空/NULL/纯空白视为“不限”。
4. **风险聚合**：命中多条取最严，规则编号全部保留并按 `rule_id` 升序、以 `;` 连接；无命中为“合规”。
5. **价格**：`Decimal(str(value))`，`ROUND_HALF_UP` 保留两位；只用数据库汇率，不硬编码。
6. **缺失/下架**：不进入规则引擎和价格模块；报告分别使用“—”和“—（不适用）”，不伪装成“合规”。
7. **Top 风险类目**：违规数降序 → 待确认数降序 → 类目名升序，取前 5；这是实现口径，不是题目指定的唯一算法。
8. **`is_deleted=1` = 已下架**：高置信度推断，尚未获得业务方单独确认，README 已如实标注。
9. **舍入方式**：题目未规定，采用 `ROUND_HALF_UP`；如业务方要求银行家舍入，需修改并同步测试。
