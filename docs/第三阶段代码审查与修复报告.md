### 3.2 CR-001：物理空行被静默跳过

| 字段 | 内容 |
|---|---|
| 缺陷编号 | CR-001 |
| 严重程度 | P1 |
| 涉及模块 | `src/compliance_assistant/loader.py` / `load_sku_inputs` |
| 问题描述 | `csv.DictReader` 会直接跳过物理空行，不产生 `row`，也不报错。当调用方未传期望数量时，记录会静默减少，违反“不得静默丢失输入”。 |
| 发现方式 | 新增边界测试 `test_blank_line_is_rejected`，修复前运行失败。 |
| 复现步骤 | 构造 CSV：`sku_ref,batch_no\n00001,B1\n\n00002,B2\n`，调用 `load_sku_inputs()`。 |
| 预期行为 | 抛出 `CsvLoadError`，错误信息包含空行行号。 |
| 实际行为 | 未抛出异常，返回 2 条记录，物理空行被静默忽略。 |
| 修复方案 | 在 `DictReader` 之前用 `csv.reader` 预扫描文件，遇到空行立即抛出 `CsvLoadError`；错误包含 `reader.line_num`。 |
| 回归测试 | `tests/test_loader.py::SkuInputLoaderTests::test_blank_line_is_rejected` |
| 修复结果 | 测试通过；正式数据无空行，120 条读取数不变。 |
| 状态 | 已修复 |

### 3.3 CR-002：重复表头未检测

| 字段 | 内容 |
|---|---|
| 缺陷编号 | CR-002 |
| 严重程度 | P1 |
| 涉及模块 | `src/compliance_assistant/loader.py` / `load_sku_inputs` |
| 问题描述 | 表头出现重复列名时，`DictReader` 只保留最后一列的值，前值被静默覆盖；例如两个 `batch_no` 会导致批次号被替换，且无任何提示。 |
| 发现方式 | 新增边界测试 `test_duplicate_header_is_rejected`，修复前运行失败。 |
| 复现步骤 | 构造 CSV：`sku_ref,batch_no,batch_no\n00001,B1,B2\n`，调用 `load_sku_inputs()`。 |
| 预期行为 | 抛出 `CsvLoadError`，明确指出重复列名。 |
| 实际行为 | 未抛出异常，返回 1 条记录且 `batch_no == "B2"`，`B1` 被静默覆盖。 |
| 修复方案 | 读取 `reader.fieldnames` 后统计重复列名，发现重复立即抛出 `CsvLoadError`。 |
| 回归测试 | `tests/test_loader.py::SkuInputLoaderTests::test_duplicate_header_is_rejected` |
| 修复结果 | 测试通过；正常两列表头不受影响。 |
| 状态 | 已修复 |

### 3.5 CR-004：极端金额/汇率泄漏 `decimal.Overflow`

| 实际行为 | 抛出未包装的 `decimal.Overflow`。 |
| 修复方案 | 将捕获范围改为 `DecimalException`，统一转换为 `PricingError` 并保留原始异常链。 |

| 状态 | 已修复 |

## 五、测试有效性审查

- 原有 97 个测试均有实质断言，未发现“只执行不断言”的测试；
