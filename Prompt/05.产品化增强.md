- HTML 报告下载。

- 异常类型和可追溯的错误编号；

- 对过期或已删除的任务结果明确提示。

## 十、第五项增强：安全处理文件上传与任务结果

本项目是在本机执行真实数据库查询的应用，必须严格处理本地文件访问风险。

### 10.1 上传文件约束

- 仅允许上传 CSV；
- 设置合理的上传大小限制，例如 2 MB；
- 校验扩展名以及真实 CSV 表头；
- 不允许把浏览器提供的文件名直接用于服务器文件路径；
- 不允许用户控制服务器上输出文件的位置；
- 不允许上传任意数据库文件替代正式数据库；
- 不执行上传文件中的代码或命令；
- 拒绝格式错误、缺少必要字段或不符合输入约定的文件。

### 10.2 临时文件与结果保存

建议将上传 CSV 保存到受控临时目录中，完成处理后及时清理。

不得永久保存用户上传的原始清单，除非项目明确提供并记录了持久化需求。

报告导出需要保存必要的结果快照时：

- 为每个任务生成随机且不可预测的 ID；
- 将结果保存在固定的服务器端目录；
- 只允许访问当前任务的预定义报告文件；
- 校验任务 ID 格式；
- 防止路径穿越；
- 不接受客户端自定义服务器文件路径；
- 为保存的明细定义清晰的数据保留与删除策略；
- 提供删除任务结果的能力或其他明确的本地清理方式。

本地报告和结果可能包含 SKU、批次等业务信息，应在界面和 README 中说明它们保存在本机的具体目录。

### 10.3 服务器边界

- 默认仅绑定 `127.0.0.1`；
- 默认关闭 Flask debug；
- 不启用交互式调试器；
- 不接入外部网络服务；
- 不发送用户输入、报告或数据库内容给外部服务；
- 不在日志中输出不必要的完整业务数据；
- 不允许在网页中指定任意数据库文件；
- 不要宣称这个本地演示应用已经具备公开互联网部署所需要的全部安全保障。

若未来需要网络部署，应将其作为独立部署项目，而不是在本阶段直接开放监听地址。

### 10.4 HTML 与 JavaScript 安全

- 使用模板自动转义；
- 使用安全的 JSON 序列化方法传递结果；
- 禁止把原始输入当作 HTML 直接插入页面；
- 用户上传内容不得执行；
- 所有文件下载接口采用服务端允许列表；
- 除非存在必要需求，否则不允许任意路径访问；
- 合理设置文件上传大小限制和响应错误处理。

## 十二、第七项增强：HTML 报告、Web 报告和 CLI 统一

这是本阶段的关键架构要求。

以下入口必须共享同一套业务核心：

- 命令行；
- HTML 报告生成；
- Web 上传检查；
- Markdown 报告导出；
- CSV 明细导出。

统一的数据流应为：

```
CSV + 只读 SQLite
        ↓
现有 loader
        ↓
现有 processor
        ↓
现有 rules_engine / pricing
        ↓
现有 validation
        ↓
统一的处理结果对象
        ↓
 ┌───────────┬───────────┬──────────┐
 │ Markdown  │ HTML 报告 │ Web 看板 │
 └───────────┴───────────┴──────────┘
```

不得出现以下情况：

- Markdown 按一种规则判定，HTML 另写一套规则；
- Web 自己硬编码风险数量；
- CSV 导出与界面显示不同；
- 一个入口将下架商品判为合规，另一个入口却显示不适用；
- HTML 报告使用不同的舍入规则；
- 前端通过修改 DOM 来改变实际业务结果。

所有展示、筛选和导出功能只能呈现后端实际处理结果。

对现有 CLI 的影响应尽量最小。默认的 `python main.py` 仍必须可以独立工作，并保持现有 Markdown 报告、业务数量和独立对账结果不变。
